# Provider Detection

`parseQRIS` reads the **Globally Unique Identifier** (sub-tag 00) from the merchant-account-info tag (**26** retail, **40**, or **51** cross-border) and maps it to a friendly provider name.

```ts
const meta = parseQRIS(qris);
meta.provider;   // "ShopeePay" | "DANA" | "Bank Mandiri" | ...
meta.issuerGui;  // "ID.CO.SHOPEE.WWW"
meta.merchantAccountInfo; // { tag: "40", gui, pan?, criteria?, fields }
```

## Supported providers

| GUI | Provider |
|---|---|
| `ID.CO.SHOPEE.WWW` | ShopeePay |
| `COM.GO-JEK.WWW` / `ID.GO-JEK.WWW` | GoPay |
| `ID.DANA.WWW` | DANA |
| `ID.OVO.WWW` | OVO |
| `ID.CO.BANKMANDIRI.WWW` | Bank Mandiri |
| `ID.CO.BCA.WWW` | BCA |
| `ID.CO.BRI.WWW` | BRI |
| `ID.CO.BNI.WWW` | BNI |
| `ID.LINKAJA.WWW` | LinkAja |
| `ID.CO.XENDIT.WWW` | Xendit |
| `ID.CO.QRIS.WWW` | QRIS (generic) |

## Unknown GUIs

If a GUI is not in the table, `provider` returns the **raw GUI string** — never throws, and the library keeps working.

> The provider map is maintained in-repo data, **not** an authoritative Bank Indonesia registry verification — not a definitive claim. `providerFromGui(gui)` exposes the same lookup for direct use.

## Verified against real issuer data

Detection is tested against real merchant QRIS: **ShopeePay** (tag 40), **Bank Mandiri** (tag 26), and **DANA** (tag 26).
