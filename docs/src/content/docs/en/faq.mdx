# FAQ & Notes

## Does qriskit reconcile payments?

**No.** Official QRIS reconciliation is **server-side** — a Payment Gateway/PSP binds the dynamic QR to an `order_id` and matches via webhook. qriskit is only a QRIS payload string-manipulation tool (parse / validate / encode) — it does not process payments, move funds, or talk to any payment server. A "unique amount suffix" (kode unik) is intentionally not provided — that's a Virtual Account technique, not the official QRIS mechanism.

## About the "QRIS" mark

## Why no QR image in core?

Because the core library is **zero-dependency**. QR image rendering (via `qrcode` and friends) is available as an **opt-in addon** — see the web demo for an example. Keeping the core clean is a design philosophy (YAGNI): anyone who needs rendering can add it without burdening those who don't.

## What's the difference between static and dynamic QRIS?

**Static** (method `11`): the customer enters the amount manually when scanning. **Dynamic** (method `12`): the amount is embedded in the QR (tag 54) — produced by `convertQRIS`.
